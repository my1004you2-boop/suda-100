# 10일 데이터 분석 과제: 10일간 내 영어는 실제로 늘었나?

수다백단 앱이 남기는 대화 로그로 **한 사용자(나)의 10일간 학습 변화**를 분석하고, 결과를 바탕으로 서비스 개선안을 제안한다.

- 기간: 2026-11-05(목, 1일차) ~ 2026-11-18(수, 10일차). 주말을 뺀 근무일 10일
- 사전 데이터: 2026-11-04 세션 3개 (기준선으로 사용)
- 최종 산출물: Notion 리포트 (800~1200자) + 분석 노트북 + 차트

---

## 1. 분석 질문

하나의 큰 질문 아래 두 갈래로 나눈다.

**메인 질문: 앱을 10일 쓰는 동안 내 영어 말하기가 실제로 나아졌는가?**

| 갈래 | 세부 질문 |
|---|---|
| A. 실수 재발·망각 | A1. 한 번 교정받은 실수를 이후 세션에서 다시 하는가? |
| | A2. 문법 실수와 어휘 실수 중 어느 쪽이 더 오래 남는가? |
| | A3. 앱이 "숨은 연습"으로 다시 꺼낸 표현을 맞게 쓰기까지 며칠이 걸리는가? |
| B. 발화 변화 | B1. 내 문장이 길어지고 어휘가 다양해졌는가? |
| | B2. 영어 문장 속 한국어 섞임, 한국어로 물어보기가 줄었는가? |
| | B3. 내가 대화를 이끄는 비율(질문하기, 먼저 이야기 꺼내기)이 늘었는가? |
| 공통 | C1. 모드(일상/비즈니스/동사/표현)와 입력 방식(음성/타자)에 따라 결과가 다른가? |
| | C2. AI 교정 데이터 자체는 믿을 만한가? (중복, 일관성) |

## 2. 데이터 소스

모두 `data/` 폴더에 있다. 앱 코드는 건드리지 않고 **이미 쌓이는 데이터만** 쓴다.

| 파일 | 단위 | 분석에 쓰는 필드 |
|---|---|---|
| `sessions/{id}.json` | 세션 1개 | `date`, `mode`, `topic`, `style`, `seconds`, `finished`, `model`, `prompt_version` |
| └ `messages[]` | 메시지 1개 | `role`, `text`, `ts`, `via_voice`, `correction`, `help_ko` |
| └ `turns[]` | 내 발화 1개에 대한 AI 판정 | `user_asked_question`, `user_led`, `mistakes[]`(`key`, `area`, `voice_sensitive`), `targets_used_correctly[]` |
| `memory.json` → `mistakes` | 실수 key 1개 (누적) | `count`, `first_seen`, `last_seen`, `last_correct`, `area` |
| `plans/{date}.json` | 하루 1개 | `targets` (그날 다시 연습시킬 실수 key), `style`, `recommended` |
| `outcomes/{id}.json` | 세션 1개 | `learned`, `repeated`, `now_correct` |
| `daily/{date}.json` | 하루 1개 | `seconds`, `user_messages`, `learned` |

**분석 전 앱 기록 개선 (2026-11-05, `PROMPT_VERSION = "2026-11-05"`)**

11/4 데이터를 보니 기록이 분석에 그대로 쓰기 어려워서 1일차 전에 앱을 고쳤다. 10일 동안은 앱을 더 고치지 않는다.

| 문제 (11/4 데이터) | 고친 내용 |
|---|---|
| key가 넓은 범주 이름이라 다른 실수가 한데 묶임 (`natural_phrasing`에 "send a mail", "so so" 등 4건) | 표현·규칙 단위의 구체적인 key를 쓰게 함 (`send_an_email`, `infinitive_purpose`). 넓은 이름은 금지하고 기존 목록에서도 숨김 |
| `area`가 자유 문자열 (`Vocabulary`, `phrasal_flow`, 한글 등) | `grammar / vocabulary / expression / spelling` 중 하나로 고정. 벗어나면 `other` |
| 판정한 모델이 기록되지 않음 | 세션에 `model`, `prompt_version` 저장 |

따라서 11/4 세션(`prompt_version == ""`)은 key·area 기준이 다르다. 기준선으로 쓸 때는 key를 수동 매핑하거나 B 지표(문장 길이, 한국어 섞임 등)에만 쓴다.

**개선 후에도 남은 문제 (11/5 1일차 데이터)**: key가 여전히 넓다. `tense_and_preposition` 하나에 "drinked", "i tell them", "on today", "had been changed" 등 8건이 묶여, 실수 23건 중 17건이 "다시 나온 실수"로 잡혔다. 11/4에 생긴 넓은 key가 기존 목록에 남아 AI가 재사용하는 것으로 보인다.
→ **결정 (11/5)**: 기간 중 앱은 고치지 않는다. **A 분석은 AI가 붙인 `key` 대신 사람이 붙이는 `mistake_id`로 한다** (3절 `mistakes.csv`, 3일차 작업). AI key와 `mistake_id`를 비교한 결과 자체도 C2(데이터 신뢰도)의 근거로 리포트에 쓴다.

실측 확인 결과 한 메시지의 실수 2개 중 하나를 놓치는 경우가 있었다("why need … i heared"에서 "heared" 누락). 4절의 AI 판정 검수에서 **누락률**도 함께 센다.

**주의할 점**
- `memory.json`은 누적값이라 `last_seen`이 계속 덮어써진다. **실수의 시간별 이력은 `sessions/`의 `turns[].mistakes`에서 다시 계산**하고, `memory.json`은 교차 검증용으로만 쓴다.
- 대화 수준(level)은 주간 평가 때만 오른다. 10일 동안 최대 한 번 바뀌므로, 바뀐 날을 기록해 두고 해석할 때 감안한다.
- `turns[]`의 판정(`user_led`, `mistakes` 등)은 Gemini가 내린 것이다. 사람이 매긴 정답이 아니므로 C2에서 일부를 직접 검수한다.

## 3. 전처리: JSON을 표 4개로

`analysis/prep.py` 하나로 `data/`를 읽어 `analysis/out/`에 CSV 4개를 만든다. 매일 저녁 다시 돌려도 결과가 같게 만든다(멱등).

**`sessions.csv`** (행 = 세션)

| 컬럼 | 설명 |
|---|---|
| `session_id`, `date`, `day_n`, `work_day` | `day_n`: 11/5부터 센 달력 날짜 (11/4 = 0, 11/5 = 1, …, 11/18 = 14). `work_day`: 근무 일차 1~10 (주말 대화는 빈 값) |
| `mode`, `style`, `topic` | |
| `minutes` | `seconds / 60` |
| `finished` | |
| `n_user_msgs`, `voice_ratio` | 내 메시지 수, 그중 음성 입력 비율 |

**`messages.csv`** (행 = 내 메시지)

| 컬럼 | 설명 |
|---|---|
| `session_id`, `date`, `day_n`, `mode`, `msg_idx` | |
| `text`, `via_voice` | |
| `n_words` | 영어 단어 수 |
| `has_korean` | 한글이 한 글자라도 섞였는지 |
| `asked_help_ko` | 한국어 도움을 받았는지 (`help_ko` 존재) |
| `corrected` | 교정 카드가 붙었는지 |
| `user_asked_question`, `user_led` | 짝이 되는 `turns[]`에서 가져옴 |
| `n_mistakes` | 이 발화에서 나온 실수 개수 |

> `messages`와 `turns`는 내 메시지 순서대로 1:1로 맞춘다. 개수가 안 맞는 세션은 경고를 찍고 따로 목록에 남긴다.

**`mistakes.csv`** (행 = 실수 1건 발생)

| 컬럼 | 설명 |
|---|---|
| `session_id`, `date`, `day_n`, `mode`, `msg_idx` | |
| `key`, `area`, `original`, `native`, `voice_sensitive` | AI가 기록한 값 그대로 |
| `mistake_id` | **사람이 붙인 실수 이름.** "틀린 말 → 맞는 말"을 보고 같은 실수끼리 같은 이름을 준다 (예: `past_tense_drink`, `do_in_why_questions`). `analysis/mistake_map.csv`(원문·교정문 → `mistake_id`)에서 가져온다 |
| `occurrence_n` | 이 `mistake_id`가 몇 번째로 나온 것인지 (1 = 처음) |

> **`mistake_id` 붙이는 기준**: 같은 학습 포인트면 같은 ID. 문법은 규칙 이름(`past_irregular_verb`: heared, drinked / `question_word_order`: "what did you watching movie"), 표현은 맞는 표현 이름(`get_much_sleep`, `need_time`). 영어 snake_case.
>
> **`mistake_map.csv` 운영** (대화 원문 조각이 들어 있어 git 제외): `prep.py`는 매핑표에 없는 실수를 `mistake_id`가 빈 행으로 매핑표 끝에 덧붙인다. 근무일마다 빈 칸만 채운다(하루 10~25건, 5~10분). 이미 있는 이름을 먼저 찾아보고, 같은 실수가 없을 때만 새 이름을 만든다.

**`practice.csv`** (행 = 숨은 연습 대상 key × 날짜)

| 컬럼 | 설명 |
|---|---|
| `date`, `key` | `plans/{date}.json`의 `targets` |
| `targeted` | 그날 연습 대상이었는지 |
| `used_correctly` | 그날 어느 세션에서든 `targets_used_correctly`에 들어갔는지 |
| `mistaken_again` | 그날 같은 key로 다시 틀렸는지 |

## 4. 데이터 품질 점검 (C2)

전처리 후 매일 확인한다. 실제로 11/4 데이터에서 이미 아래 1, 2번이 발견됐다.

| # | 점검 항목 | 방법 | 11/4 사례 |
|---|---|---|---|
| 1 | 같은 교정의 중복 | 일일 리포트 `learned`에서 `original`이 같은 항목 | "i don't have long sleep" 교정이 설명만 다르게 2번 |
| 2 | 같은 날 주제 반복 | `sessions.csv`에서 날짜별 `topic` 중복 | "출퇴근길 이야기"가 하루에 2번 |
| 3 | AI key의 정확도 | `mistake_id` 기준과 AI `key` 기준을 비교: 다른 실수를 한 key로 묶은 비율, 같은 실수를 다른 key로 나눈 비율 | 11/5 `tense_and_preposition`에 서로 다른 실수 8건 |
| 4 | messages와 turns 개수 불일치 | 전처리 경고 목록 | |
| 5 | 아주 짧은 세션 | 3분 미만 세션 (11/4 마지막 세션은 108초) | 분석에서 뺄지 따로 표시할지 결정 |
| 6 | 말하지 않은 실수 기록 | AI가 적은 "틀린 말"의 단어 80% 이상이 내 메시지에 없으면 `not_in_text` (자동) | 11/6 "so so" (그 메시지는 "Very nice. they were full of praise.") |
| 7 | 한 메시지 안 중복 실수 | 같은 "틀린 말"이 한 메시지에 두 번 기록되면 `dup_in_msg` (자동) | |

6·7번에 걸린 기록은 `valid = False`로 두고 재발 계산에서 뺀다.

**AI 판정 검수**: 10일차 전에 내 메시지 30개를 무작위로 골라 `corrected`, `user_led`, `area`가 맞는지 직접 판정한다. 일치율을 리포트에 적는다. (예: "AI의 `user_led` 판정은 30건 중 26건 일치")

## 5. 지표 정의

### A. 실수 재발·망각

| 지표 | 정의 | 해석 |
|---|---|---|
| **재발률** | (2번 이상 나온 `mistake_id` 수) / (전체 `mistake_id` 수). A 지표는 모두 `mistake_id` 기준 | 낮을수록 좋음 |
| **유형별 재발률** | 위 값을 `area`(grammar / vocabulary 등)별로 | A2 답 |
| **재발 간격** | 같은 key의 연속 발생 사이 일수의 중앙값 | 며칠 뒤에 다시 틀리는가 |
| **회복 소요일** | 첫 발생일부터 처음 `used_correctly`가 된 날까지의 일수 | A3 답 |
| **연습 성공률** | `practice.csv`에서 `targeted`인 행 중 `used_correctly` 비율 | 숨은 연습 기능의 효과 |
| **신규 실수 비율** | 일자별 실수 중 `occurrence_n == 1` 비율 | 새로운 걸 시도하는 정도로도 읽힘 |

### B. 발화 변화

| 지표 | 정의 |
|---|---|
| **평균 문장 길이** | 일자별 `n_words` 평균 (중앙값도 함께) |
| **어휘 다양성** | 일자별로 내 메시지를 합쳐 앞 150단어만 잘라 계산한 TTR (서로 다른 단어 수 / 전체 단어 수). 날마다 말한 양이 다르므로 길이를 맞춘다 |
| **한국어 섞임률** | `has_korean` 비율 |
| **도움 요청률** | `asked_help_ko` 비율 |
| **교정 비율** | `corrected` 비율 (낮을수록 좋지만, 수준이 오르면 다시 높아질 수 있음) |
| **발화당 실수 수** | `n_mistakes` 평균 |
| **주도율** | `user_led` 또는 `user_asked_question`이 참인 비율 |

### 공통 분할 기준

모든 지표를 아래 기준으로 나눠서도 본다: `mode`, `via_voice`, 전반(11/5~11/11) vs 후반(11/12~11/18). 주말에 한 대화도 날짜 기준으로 전반·후반에 넣는다.

## 6. 분석 방법

표본이 작으니(사용자 1명, 하루 1~3세션) 통계적 유의성보다 **방향과 크기**를 본다.

1. **일자별 추이**: 지표마다 일자별 값 + 3일 이동평균 선 그래프.
2. **전반 vs 후반 비교**: 1~5일차와 6~10일차의 평균 차이. 메시지 단위로 부트스트랩 95% 신뢰구간을 붙여 "차이가 우연일 수 있는지"만 가늠한다.
3. **실수 생존 분석(간단 버전)**: 실수 key별로 처음 나온 날부터 "다시 틀리지 않은 날 수"를 세서 유형별 곡선을 그린다. 정식 Kaplan-Meier까지는 안 가도 된다.
4. **모드·입력 방식 비교**: 지표 × 모드, 지표 × 음성/타자 표. 칸마다 표본 수를 같이 적는다.
5. **사례 보기**: 숫자로 본 변화를 실제 문장 2~3쌍으로 보여 준다. (예: 1일차 "why need more time?" → 8일차 "Why do you need more time?")

내 대화 원문이 들어 있으므로 `analysis/out/`과 `data/`는 공개 저장소에 올리지 않는다. 리포트에 인용하는 문장만 골라서 쓴다.

## 9. 최종 리포트 구성 (Notion, 800~1200자)

| 섹션 | 분량 | 내용 |
|---|---|---|
| 1. 배경 | ~100자 | 무엇을, 왜, 어떤 데이터로 봤는가 |
| 2. 핵심 결과 | ~400자 | 늘어난 것 2~3개, 그대로인 것 1~2개 (수치 + 차트 2개) |
| 3. 원인 진단 | ~300자 | 왜 그런 결과가 나왔는가 (예: 어휘 실수는 숨은 연습 대상에 덜 뽑혀서 재발이 잦다) |
| 4. 서비스 개선안 | ~300자 | 데이터에 근거한 제안 2~3개 |
| 5. 한계 | ~100자 | n=1, 10일, AI 판정 의존, 수준 변화 |

**개선안 후보** (결과에 따라 고른다)
- 일일 리포트의 중복 교정을 합치기 (품질 점검 1번 근거)
- 하루 안에 같은 주제가 다시 배정되지 않게 하기 (품질 점검 2번 근거)
- 재발 간격에 맞춰 숨은 연습 노출 주기를 조정하기 (A 재발 간격 근거)
- 음성 입력에서만 나는 실수는 실수 기록과 따로 관리하기 (C1 근거)

## 10. 한계와 대응

| 한계 | 대응 |
|---|---|
| 사용자 1명, 10일 | 일반화하지 않는다. "이 사용자에게 이 앱이 어땠나"로 범위를 좁혀 쓴다 |
| 하루 세션 수가 들쭉날쭉 | 일자 단위보다 메시지 단위 지표를 우선하고, 표본 수를 항상 같이 표기 |
| 실수 판정이 AI 기준 | 30건 직접 검수, 일치율 공개 |
| 주제·모드가 날마다 달라 난이도가 다름 | 모드별로 나눠 보고, 같은 모드끼리 전후를 비교 |
| 내가 분석자이자 피험자 | 분석 중간에 지표를 보고 일부러 행동을 바꾸지 않는다. 중간 점검(5일차, 11/11) 외에는 결과 차트를 보지 않는다 |
